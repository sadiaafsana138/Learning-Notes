### প্রতিটি তথ্যের পিছনের যুক্তি

> সত্যিকারের মুখস্থ করার জিনিস মাত্র **১৫টা** — একদম শেষে আলাদা করে দেওয়া আছে।

> **পড়ার নিয়ম:** প্রতিটি অংশে আগে প্রশ্নটা নিজে ভাবো, তারপর উত্তর দেখো।

# 🌐 NETWORKING

## ❓ Block Size = 256 − mask — কেন?

Mask হলো "কতটুকু Network"। বাকিটা Host।

`/26` → mask `192` → binary `11000000` → শেষ octet-এ **2টা network bit, 6টা host bit**

একটা subnet-এ ঠিকানা = `2⁶ = 64`। পরের subnet শুরু হবে ৬৪ পরে।

**256 − 192 = 64** — এটা আসলে *"পুরো octet (256) থেকে network অংশ বাদ দিলে যা থাকে"*।

➡️ **সূত্র নয়, বিয়োগের অর্থ।**

---

## ❓ Mask-এর octet মাত্র ৯টা সংখ্যা — কেন?

Mask-এ 1 মানে Network, 0 মানে Host। **Network অংশ সবসময় সামনে**, Host পিছনে — মাঝখানে ভাগ করা যায় না।

তাই 1-গুলো **টানা বাম থেকে** বসবেই। ৮ bit-এ সম্ভাবনা: 0টা 1, 1টা, 2টা … 8টা → **মোট ৯টা**।

`191 = 10111111` — মাঝে 0, তারপর আবার 1। মানে "Host, তারপর আবার Network" — অর্থহীন। তাই অবৈধ।

➡️ **তালিকা মুখস্থ করার দরকার নেই — "টানা বাম থেকে" মনে রাখলেই হলো।**

---

## ❓ Class A শেষ হয় 126-এ, 127-এ নয় — কেন?

127 কোনো class নয়। পুরো `127.0.0.0/8` block **loopback**-এর জন্য কেটে রাখা — কম্পিউটার নিজের সাথে কথা বলতে ব্যবহার করে।

Class A ছিল `1–127`, কিন্তু 127 কেটে নেওয়ায় **1–126** হয়ে গেছে।

➡️ **নিয়ম নয়, একটা ব্যতিক্রমের ফল।**

---

## ❓ TCP ধীর, UDP দ্রুত — কেন?

Header দেখো: **TCP 20 byte, UDP 8 byte**। এই ১২ byte পার্থক্যেই সব উত্তর।

TCP-র বাড়তি ১২ byte-এ থাকে — sequence number (ক্রম ঠিক রাখতে), ACK number (পৌঁছেছে কিনা), window size (flow control), flag।

**এগুলোই TCP-কে নির্ভরযোগ্য বানায়, এগুলোই ধীর করে।** UDP এসব রাখে না, তাই দ্রুত কিন্তু অনির্ভরযোগ্য।

➡️ **নির্ভরযোগ্যতার দাম = গতি।** দুটোর মধ্যে একটাই বাছা যায়।

---

## ❓ DNS ও DHCP UDP ব্যবহার করে — কেন?

DNS query একটামাত্র ছোট প্রশ্ন: *"google.com-এর IP কী?"*

TCP ব্যবহার করলে আগে **three-way handshake** (৩টা packet), তারপর প্রশ্ন, তারপর উত্তর, তারপর ৪ packet-এ সংযোগ বন্ধ — মোট ৯টা packet একটা ছোট প্রশ্নের জন্য।

UDP-তে: প্রশ্ন পাঠাও, উত্তর নাও — **২টা packet**। উত্তর না এলে আবার জিজ্ঞেস করলেই হলো।

➡️ **ছোট ও পুনরাবৃত্তিযোগ্য কাজে TCP-র খরচ পোষায় না।**

---

## ❓ Handshake তিন ধাপ, দুই নয় — কেন?

দুই পক্ষকেই নিশ্চিত হতে হবে যে **তারা পাঠাতেও পারছে, পেতেও পারছে**।

```
SYN     →  A বলল "আমি পাঠাতে পারি"
SYN-ACK →  B বলল "তোমারটা পেয়েছি, আমিও পাঠাতে পারি"
ACK     →  A বলল "তোমারটাও পেয়েছি"
```

দুই ধাপে থামলে **B কখনো জানত না তার বার্তা A পেয়েছে কিনা**।

➡️ **প্রতিটি দিক আলাদাভাবে যাচাই করতে ৩ ধাপ লাগেই।**

---

## ❓ Wi-Fi-তে CSMA/CD চলে না — কেন?

CD মানে **Collision Detection** — পাঠানোর সময় শুনতে থাকা।

কিন্তু বেতারে নিজের signal এত জোরালো যে অন্যেরটা শোনাই যায় না — যেন চিৎকার করতে করতে ফিসফিস শোনার চেষ্টা।

আর **Hidden Terminal**: A ও C একে অপরকে শুনতে পায় না, দুজনেই B-কে পায়। দুজনেই ভাববে লাইন খালি।

➡️ **শুনতে না পারলে ধরা যায় না, তাই আগেই এড়াতে হয় (CA)।**

---

## ❓ Hub সবাইকে পাঠায়, Switch পাঠায় না — কেন?

**Hub = Layer 1.** সে শুধু বৈদ্যুতিক সংকেত দেখে, **address বোঝে না**। না বুঝলে সিদ্ধান্ত নেওয়ার উপায়ও নেই — তাই সবাইকে দেয়।

**Switch = Layer 2.** সে **MAC address পড়তে পারে**, আর একটা table-এ মনে রাখে কোন MAC কোন port-এ। তাই সরাসরি সঠিক port-এ পাঠায়।

➡️ **যে layer-এ কাজ করে, সে ততটুকুই বুঝতে পারে।** Router (L3) IP বোঝে, তাই ভিন্ন network চেনে।

---

## ❓ Private IP Internet-এ চলে না — কেন?

`192.168.1.5` কোটি কোটি বাসায় একই সময়ে ব্যবহৃত হচ্ছে। Internet-এর router কীভাবে বুঝবে **কোন** 192.168.1.5?

পারে না — তাই private range গুলো Internet-এ **routing করাই হয় না**।

**NAT** এজন্যই দরকার: তোমার router private IP-কে নিজের public IP-তে বদলে পাঠায়, উত্তর এলে আবার ফিরিয়ে দেয়।

➡️ **অনন্য না হলে খুঁজে পাওয়া যায় না।**

---

## ❓ IPv6 এসেছে — কেন?

IPv4 = 32 bit = `2³²` ≈ **4.3 বিলিয়ন**। পৃথিবীর মানুষই ৮ বিলিয়ন, তার উপর প্রত্যেকের ফোন-ল্যাপটপ-ঘড়ি-টিভি।

IPv6 = 128 bit = `2¹²⁸` ≈ 3.4 × 10³⁸ — কার্যত অফুরন্ত।

➡️ **সংখ্যাটা ফুরিয়ে গিয়েছিল, তাই ঘর বাড়াতে হয়েছে।**

# 🗄️ DATABASE

## ❓ Primary Key NULL হতে পারে না — কেন?

PK-র একমাত্র কাজ **প্রতিটি row-কে আলাদা করে চেনা**।

NULL মানে "মান জানা নেই"। যা জানা নেই, তা দিয়ে চেনা যায় না। দুটো row-তেই NULL থাকলে কোনটা কোনটা?

➡️ **কাজটাই অসম্ভব হয়ে যায়, তাই নিয়ম।**

## ❓ কিন্তু Foreign Key NULL হতে পারে — কেন?

FK-র কাজ **সম্পর্ক দেখানো**। সম্পর্ক না-ও থাকতে পারে।

একজন নতুন employee যার এখনো বিভাগ ঠিক হয়নি — তার `DeptID` NULL। সে employee ঠিকই আছে, শুধু সম্পর্কটা এখনো তৈরি হয়নি।

➡️ **"পরিচয়" বাধ্যতামূলক, "সম্পর্ক" ঐচ্ছিক।**

---

## ❓ 1NF → 2NF → 3NF — এই ক্রম কেন?

প্রতিটি NF **একটি নির্দিষ্ট রোগ** সারায়, ধাপে ধাপে:

| NF | কোন রোগ | কেন এই ক্রমে |
|---|---|---|
| **1NF** | এক ঘরে একাধিক মান | ঘর ঠিক না হলে নির্ভরতা বিশ্লেষণই করা যায় না |
| **2NF** | Key-র **অংশের** উপর নির্ভরতা | composite key থাকলেই এটা সম্ভব |
| **3NF** | Non-key → non-key নির্ভরতা | সবচেয়ে সূক্ষ্ম, শেষে |

➡️ **আগেরটা না সারিয়ে পরেরটা ধরা যায় না — এজন্যই ক্রম।**

⭐ এজন্যই **PK একটা column হলে 2NF আপনাআপনি হয়ে যায়** — key-র "অংশ" বলে কিছু নেই, তাই partial dependency-ই অসম্ভব।

---

## ❓ WHERE-এ COUNT() চলে না — কেন?

Query চলার ক্রম দেখো:
```
FROM → WHERE → GROUP BY → HAVING → SELECT
```

`WHERE` চলে **GROUP BY-এর আগে**। তখনো group তৈরিই হয়নি — গুনবে কী?

`HAVING` চলে **পরে**, তখন group আছে, তাই COUNT() চলে।

➡️ **নিয়ম নয়, সময়ের ব্যাপার।** যা এখনো তৈরি হয়নি তা ব্যবহার করা যায় না।

---

## ❓ Index থাকলে SELECT দ্রুত কিন্তু INSERT ধীর — কেন?

Index একটা **আলাদা সাজানো structure** (B+ Tree)।

- **SELECT**: সাজানো থাকায় সরাসরি খুঁজে পায় → দ্রুত
- **INSERT**: নতুন row বসানোর পর **index-টাও আপডেট করতে হয়**, tree আবার সাজাতে হয় → বাড়তি কাজ

➡️ **সাজিয়ে রাখার সুবিধা আছে, সাজিয়ে রাখার খরচও আছে।**

# 💻 PROGRAMMING

## ❓ 5/2 = 2 — কেন?

দুটোই **integer**। C/Java-তে integer ÷ integer = **integer**। ভগ্নাংশ কেটে ফেলে (truncate, round নয়)।

`5.0/2` লিখলে একটা float হয়ে যায় → ফল float → **2.5**

➡️ **ফলের ধরন নির্ভর করে উপাদানের ধরনের উপর।**

## ❓ float-এ `%` চলে না — কেন?

`%` মানে "ভাগ করে যা বাকি থাকে"। Integer-এ "বাকি" স্পষ্ট।

কিন্তু `3.14 ÷ 2.1` = 1.495... — এখানে "বাকি" ধারণাটাই আলাদাভাবে সংজ্ঞায়িত করতে হয়। এজন্য আলাদা function: **`fmod()`**।

➡️ **আলাদা ধারণা, তাই আলাদা হাতিয়ার।**

---

## ❓ `i++` আর `++i` আলাদা — কেন?

দুটোই i-কে ১ বাড়ায়। পার্থক্য **কোন মানটা ফেরত দেয়**:

```
i = 5
j = i++    →  j পায় 5 (পুরনো), তারপর i হয় 6     "আগে দাও, পরে বাড়াও"
j = ++i    →  i হয় 6, তারপর j পায় 6            "আগে বাড়াও, পরে দাও"
```

➡️ **নামেই আছে:** `++` আগে থাকলে আগে বাড়ে, পরে থাকলে পরে বাড়ে।

---

## ❓ `&&` short-circuit করে — কেন?

`A && B` — A যদি **false** হয়, B যাই হোক ফল **false**-ই। তাহলে B হিসাব করে সময় নষ্ট কেন?

শুধু গতি নয়, **নিরাপত্তাও**:
```c
if (ptr != NULL && ptr->value > 0)
```
ptr যদি NULL হয়, প্রথমটা false → দ্বিতীয়টা **চলেই না** → crash বাঁচল।

➡️ **এটা optimization নয়, ভাষার নিশ্চয়তা** — তাই Q8-এর মতো প্রশ্নে j++ চলবে না।

---

## ❓ Java platform-independent, C নয় — কেন?

**C compiler** সরাসরি **নির্দিষ্ট CPU-র machine code** বানায়। Windows-এর .exe Linux-এ চলবে না।

**Java compiler** বানায় **bytecode** — কোনো CPU-র ভাষা নয়, JVM-এর ভাষা। প্রতিটি OS-এর নিজস্ব JVM আছে, যে bytecode-কে নিজের machine code-এ বদলে নেয়।

```
C     :  Source → [OS-নির্দিষ্ট machine code]        একবার লিখে একটাতেই চলে
Java  :  Source → Bytecode → [JVM] → machine code    একবার লিখে সবখানে চলে
```

➡️ **মাঝখানে একটা অনুবাদক বসানো হয়েছে।** Bytecode সবার জন্য এক, JVM প্রত্যেকের আলাদা।

---

## ❓ Overloading compile-time, Overriding run-time — কেন?

**Overloading:** `print(int)` আর `print(String)` — argument-এর ধরন দেখে compiler **তখনই** বলে দিতে পারে কোনটা ডাকা হবে।

**Overriding:** `Animal a = new Dog()` — variable-এর ধরন Animal, কিন্তু আসল object Dog। **কোন object সেটা জানা যায় শুধু চলার সময়**, তাই সিদ্ধান্তও তখনই।

➡️ **যে তথ্য আগে জানা যায়, সিদ্ধান্ত আগে; যা পরে জানা যায়, সিদ্ধান্ত পরে।**

# ⚙️ OPERATING SYSTEMS

## ❓ Thread তৈরি সস্তা, Process ব্যয়বহুল — কেন?

**Process** তৈরিতে OS-কে নতুন **memory space** বানাতে হয় — code, data, heap, stack সব আলাদা।

**Thread** একই process-এর ভিতরে জন্মায়, **memory শেয়ার করে** — শুধু নিজের stack আর register লাগে।

➡️ **নতুন বাড়ি বানানো vs সেই বাড়িতে আরেকটা ঘর।**

আর এজন্যই **একটা thread crash করলে পুরো process যেতে পারে** — সবাই একই memory-তে থাকে।

---

## ❓ Deadlock-এর চারটা শর্তই লাগে — কেন?

চারটা একসাথে না হলে deadlock ভেঙে যায়:

| শর্ত | না থাকলে |
|---|---|
| Mutual Exclusion | সবাই একসাথে ব্যবহার করতে পারত, আটকাত না |
| Hold and Wait | ধরে রেখে অপেক্ষা না করলে জট বাঁধত না |
| No Preemption | জোর করে কেড়ে নিলে জট খুলে যেত |
| Circular Wait | বৃত্ত না হলে কোথাও না কোথাও শেষ হতো |

➡️ **এজন্যই deadlock prevention-এর কৌশল = যেকোনো একটা শর্ত ভেঙে দেওয়া।**

---

## ❓ Round Robin-এ Circular Queue — কেন?

প্রতিটি process নির্দিষ্ট সময় (quantum) পায়। শেষ হলে **লাইনের পিছনে** গিয়ে দাঁড়ায়, আবার তার পালা আসে।

সাধারণ Queue-তে সামনে খালি জায়গা নষ্ট হয়। Circular Queue-তে শেষ থেকে আবার শুরুতে ফেরা যায় — ঠিক যেমন পালা ঘুরে ঘুরে আসে।

➡️ **কাজের প্রকৃতিই বৃত্তাকার, তাই structure-ও বৃত্তাকার।**

# 🌳 DATA STRUCTURES

## ❓ Array-তে access O(1), Linked List-এ O(n) — কেন?

Array **contiguous** — ঠিকানা হিসাব করে ফেলা যায়:
```
Address(A[i]) = Base + i × size
A[500] = 1000 + 500 × 4 = 3000    ← এক হিসাবেই পৌঁছে গেলাম
```

Linked List-এ node **ছড়িয়ে-ছিটিয়ে**। ৫০০ নম্বরে যেতে হলে ১ থেকে শুরু করে **pointer ধরে ধরে হাঁটতে হবে** — কারণ ঠিকানা জানার একমাত্র উপায় আগের node।

➡️ **হিসাব করে পৌঁছানো vs হেঁটে পৌঁছানো।**

## ❓ কিন্তু Linked List-এ insert O(1), Array-তে O(n) — কেন?

Array-তে মাঝে ঢোকাতে হলে **ডানের সবাইকে সরাতে হয়** (contiguous রাখতে হবে)।

Linked List-এ শুধু **দুটো pointer বদলাতে হয়** — কেউ নড়ে না।

➡️ **একই কারণ (contiguous কিনা) থেকে উল্টো ফল।** এজন্যই কোনো DS "সেরা" নয়।

---

## ❓ Binary Search O(log n) — কেন?

প্রতি ধাপে **অর্ধেক বাদ** যায়:
```
1000 → 500 → 250 → 125 → 62 → 31 → 15 → 7 → 3 → 1
```
১০ ধাপ। কারণ `2¹⁰ ≈ 1000`।

"কতবার অর্ধেক করলে ১-এ পৌঁছাব?" — এই প্রশ্নের উত্তরই **log₂ n**।

➡️ **log মানেই "কতবার ভাগ করলে শেষ হবে"।** যেকোনো জায়গায় অর্ধেক হতে দেখলেই log।

---

## ❓ BST-র Inorder = sorted — কেন?

BST-র নিয়ম: **বামে ছোট, ডানে বড়**।
Inorder-এর নিয়ম: **বাম → root → ডান**।

মানে প্রতিটি node-এ: আগে সব ছোট, তারপর নিজে, তারপর সব বড়। এটাই তো ক্রম!

➡️ **দুটো নিয়ম একই কথা বলছে — তাই ফল sorted।** মুখস্থ নয়, অনিবার্য।

---

## ❓ n নোডের tree-তে edge = n − 1 — কেন?

Root ছাড়া **প্রতিটি node-এর ঠিক একটা parent**। আর প্রতিটি parent-child সম্পর্ক = একটা edge।

তাই edge সংখ্যা = parent আছে এমন node সংখ্যা = **n − 1** (root বাদ)।

➡️ **গোনার প্রশ্ন, সূত্রের নয়।**

## ❓ Level i-তে সর্বোচ্চ 2ⁱ নোড — কেন?

প্রতিটি node সর্বোচ্চ **২টি** child দিতে পারে। তাই প্রতি level-এ সংখ্যা **দ্বিগুণ** হয়:
```
Level 0:  1  =  2⁰
Level 1:  2  =  2¹
Level 2:  4  =  2²
```

➡️ **"Binary" মানেই দুই — তাই দ্বিগুণ।**

---

## ❓ Build Heap = O(n), অথচ n বার insert = O(n log n) — কেন?

Insert করলে প্রতিটি element **নিচ থেকে উপরে** উঠতে পারে — পুরো উচ্চতা, log n।

কিন্তু Build Heap **নিচ থেকে শুরু করে**। আর tree-র **অর্ধেক node-ই leaf** — তাদের কিছুই করতে হয় না। উপরের দিকের অল্প কিছু node-ই বেশি নামে।

```
n/2 টা node  →  0 ধাপ  (leaf)
n/4 টা node  →  1 ধাপ
n/8 টা node  →  2 ধাপ
```
যোগ করলে **O(n)**, O(n log n) নয়।

➡️ **বেশিরভাগ node-ই নিচে, আর নিচের node-দের কাজ কম।**

---

## ❓ Hash Table O(1) কিন্তু sorted order দেয় না — কেন?

Hash function ইচ্ছাকৃতভাবে key-গুলোকে **এলোমেলোভাবে ছড়িয়ে** দেয় — যাতে collision কম হয়।

`h(k) = k % 10` → 25 যায় index 5-এ, 26 যায় index 6-এ, কিন্তু 35-ও যায় index 5-এ। ক্রমের কোনো চিহ্নই থাকে না।

➡️ **ছড়ানোই তার কাজ, আর ছড়ালে ক্রম থাকে না।** ক্রম দরকার হলে BST।

---

## ❓ Merge Sort-এর O(n) space লাগে, Heap Sort-এর লাগে না — কেন?

**Merge** করতে হলে দুটো sorted অংশ থেকে তুলনা করে নতুন জায়গায় বসাতে হয়। একই array-তে করলে আগের মান চাপা পড়ে যাবে — তাই **আলাদা array** লাগে।

**Heap Sort** শুধু **swap** করে — root আর শেষের element জায়গা বদল। বাড়তি জায়গা লাগেই না।

➡️ **নতুন জায়গায় লেখা vs জায়গা বদল।**

---

## ❓ Quick Sort-এর worst case O(n²) — কেন?

Quick Sort ভরসা করে যে pivot **মোটামুটি মাঝখানে** পড়বে, তাহলে অর্ধেক-অর্ধেক ভাগ হবে → log n স্তর।

কিন্তু already sorted array-তে first element pivot নিলে — pivot সবসময় **সবচেয়ে ছোট**। একদিকে ০টা, অন্যদিকে n−1টা। ভাগই হলো না।

```
n → n−1 → n−2 → ... → 1     (n স্তর, প্রতি স্তরে n কাজ)  =  n²
```

➡️ **ভাগ করতে না পারলে Divide & Conquer-এর সুবিধাই থাকে না।**

---

## ❓ Recursion Stack ব্যবহার করে — কেন?

`factorial(4)` চলার সময় `factorial(3)`-এর জন্য অপেক্ষা করে। তার মানে **4-এর অবস্থা মনে রাখতে হবে**, 3 শেষ হলে ফিরে আসতে হবে।

সবচেয়ে **শেষে ডাকা** function সবচেয়ে **আগে শেষ** হয় — এটাই **LIFO**, এটাই Stack।

➡️ **Stack ব্যবহার করে না — Stack ছাড়া recursion সম্ভবই নয়।**

---

## ❓ Comparison sort O(n log n)-এর চেয়ে দ্রুত হতে পারে না — কেন?

n টা element-এর সম্ভাব্য সাজানো = **n!** টা।

প্রতিটি তুলনা (`a > b?`) দুটো উত্তর দেয় — মানে সম্ভাবনা **অর্ধেক** করে। n! সম্ভাবনা থেকে ১টায় পৌঁছাতে `log₂(n!)` ≈ **n log n** তুলনা লাগবেই।

**Counting Sort তুলনা করেই না** — সরাসরি গুনে ফেলে। তাই এই সীমা তার জন্য খাটে না।

➡️ **তুলনার সংখ্যায় গাণিতিক সীমা আছে। সীমা এড়াতে হলে তুলনা বাদ দাও।**

# 🔢 DIGITAL LOGIC

## ❓ দশমিকের ডানে ঘর মান ½, ¼, ⅛ — কেন?

দশমিকের **বামে** প্রতি ঘরে ভিত্তি (2) দিয়ে **গুণ**: 1, 2, 4, 8...
তাই **ডানে** প্রতি ঘরে **ভাগ**: ½, ¼, ⅛...

```
   8    4    2    1  .  ½    ¼    ⅛
   ←──── ×2 ────    │    ──── ÷2 ────→
```

দশমিক সংখ্যাতেও একই — বামে 10, 100; ডানে 0.1, 0.01।

➡️ **একই নিয়ম, শুধু ভিত্তি 10-এর বদলে 2।**

---

## ❓ 2's complement কাজ করে — কেন?

উদ্দেশ্য: **বিয়োগকে যোগে বদলানো**, যাতে আলাদা circuit না লাগে।

8 bit-এ সর্বোচ্চ + 1 = 256। যদি এমন একটা সংখ্যা বানাই যেটা `B` যোগ করলে **256** হয়, তাহলে সেটা যোগ করা মানে **B বিয়োগ করা** — কারণ 256 উপচে (overflow) হারিয়ে যায়।

সেই সংখ্যাটাই `256 − B` = **B-র 2's complement** = (সব bit উল্টাও) + 1।

➡️ **উপচে পড়া carry-টাই কৌশল।** তাই শেষ carry ফেলে দেওয়া হয়।

---

## ❓ NAND ও NOR "Universal" — কেন?

যেকোনো circuit বানাতে **AND, OR, NOT** — এই তিনটাই যথেষ্ট। NAND দিয়ে তিনটাই বানানো যায়:

```
NOT  =  NAND(A, A)
AND  =  NOT(NAND(A,B))     =  NAND-এর পর আরেকটা NAND
OR   =  NAND(NOT A, NOT B)
```

তিনটা বানাতে পারলে **সবই** বানানো যায়।

➡️ শিল্পে এর মূল্য: **এক ধরনের gate দিয়েই পুরো chip** — উৎপাদন সস্তা ও সহজ।

# 🤖 ML

## ❓ Imbalanced data-তে Accuracy বিভ্রান্তিকর — কেন?

১০০০ email-এর ৯৯০টা normal, ১০টা spam।

একটা model যা **সবসময় "normal" বলে** — কিছুই শেখেনি — তার accuracy **99%**।

কিন্তু সে **একটাও spam ধরতে পারেনি**। Accuracy সংখ্যাটা সত্যি, কিন্তু অর্থহীন।

Recall দেখলে ধরা পড়ে: `TP/(TP+FN)` = `0/10` = **0%** ❌

➡️ **সংখ্যাগরিষ্ঠতাই যেখানে উত্তর, সেখানে "সবসময় সংখ্যাগরিষ্ঠ বলা" ভালো নম্বর পায়।**

## ❓ Activation function ছাড়া গভীর network অর্থহীন — কেন?

Activation না থাকলে প্রতিটি layer শুধু `wx + b` — একটা **সরলরৈখিক** রূপান্তর।

সরলরৈখিক রূপান্তরের উপর আরেকটা সরলরৈখিক রূপান্তর = **আবার সরলরৈখিক**।

১০০টা layer দিলেও শেষ পর্যন্ত একটা সরলরেখাই — ১টা layer-এর সমান।

➡️ **Non-linearity ছাড়া গভীরতার কোনো মূল্য নেই।**
