# CSE 470 — SOFTWARE ENGINEERING

## 1. Software Engineering
**English:** Software engineering is the systematic, disciplined approach to the development, operation, maintenance, and evolution of software.  
**বাংলা:** Software তৈরি, test, maintain ও evolve করার systematic ও disciplined process হলো software engineering।

## 2. Software Process
**English:** A software process is a structured set of activities used to develop and maintain software, such as requirements, design, implementation, testing, and maintenance.  
**বাংলা:** Software development-এর বিভিন্ন কাজকে structuredভাবে পরিচালনার process।

## 3. Requirements
**English:** Requirements describe what the software must do and the constraints under which it must operate.  
**বাংলা:** Software কী করবে এবং কী constraint follow করবে তা requirements-এ বলা হয়।

## 4. Requirements Definition
**English:** Requirements definition documents the required services, functions, constraints, and expected behavior of a system.  
**বাংলা:** System-এর required function, service, constraint ও behavior clearly define/document করা।

## 5. Functional Requirement
**English:** A functional requirement specifies a service or behavior that the system must provide.  
**বাংলা:** System কী কাজ করবে তা functional requirement বলে।

## 6. Non-Functional Requirement
**English:** A non-functional requirement specifies quality attributes or constraints such as performance, security, reliability, and usability.  
**বাংলা:** System কত ভালোভাবে কাজ করবে—যেমন speed, security, reliability—তা non-functional requirement।

## 7. Requirements Specification
**English:** Requirements specification is the documented description of the system's agreed requirements, serving as a basis for design and development.  
**বাংলা:** Agreed requirements-কে formal/documented form-এ রাখা হয়।

## 8. Requirements Validation
**English:** Requirements validation checks whether requirements are correct, complete, consistent, feasible, and testable.  
**বাংলা:** Requirement ভুল, incomplete, contradictory বা unrealistic কিনা verify করা হয়।

## 9. Modular Design
**English:** Modular design divides a software system into smaller, relatively independent modules with well-defined responsibilities and interfaces.  
**বাংলা:** বড় system-কে ছোট independent/loosely coupled module-এ ভাগ করা।

## 10. Module
**English:** A module is a self-contained software component that performs a specific responsibility.  
**বাংলা:** নির্দিষ্ট কাজের জন্য তৈরি software component হলো module।

## 11. Cohesion
**English:** Cohesion measures how closely related the responsibilities within a module are; high cohesion is generally desirable.  
**বাংলা:** একটি module-এর ভিতরের কাজগুলো কতটা related তা cohesion; high cohesion ভালো।

## 12. Coupling
**English:** Coupling measures the dependency between modules; low coupling is generally desirable.  
**বাংলা:** এক module অন্য module-এর ওপর কতটা dependent তা coupling; low coupling ভালো।

## 13. Structure Design
**English:** Structured design organizes a system into modules and defines their relationships and control/data flow.  
**বাংলা:** System-কে structured module-এ ভাগ করে তাদের relationship ও flow design করা।

## 14. Data Specification
**English:** Data specification defines the data structures, data elements, formats, relationships, and constraints used by the system.  
**বাংলা:** System-এর data কীভাবে structured, formatted ও related হবে তা define করে।

## 15. Functional Specification
**English:** Functional specification describes system functions, inputs, processing, outputs, and expected behavior in sufficient detail for implementation.  
**বাংলা:** Function-এর input → processing → output কী হবে তা detail-এ describe করে।

## 16. Software Verification
**English:** Verification asks whether the software is being built according to its specified requirements and design.  
**বাংলা:** “Are we building the product right?”—specification অনুযায়ী software বানানো হচ্ছে কিনা check করা।

## 17. Validation
**English:** Validation asks whether the developed software satisfies the user's actual needs and intended use.  
**বাংলা:** “Are we building the right product?”—user-এর actual need meet করছে কিনা check করা।

## 18. Verification vs Validation
**English:** Verification checks conformance to specifications; validation checks fitness for user needs.  
**বাংলা:** Verification = specification ঠিকমতো follow হয়েছে কিনা; Validation = user-এর প্রয়োজন পূরণ হয়েছে কিনা।

## 19. Testing
**English:** Software testing executes or evaluates software to find defects and assess whether it satisfies specified requirements.  
**বাংলা:** Software-এর defect খুঁজে requirements satisfy করছে কিনা check করা।

## 20. Documentation
**English:** Software documentation records requirements, design, code-related information, operation, testing, and maintenance information.  
**বাংলা:** Software সম্পর্কে প্রয়োজনীয় technical/user information লিখিতভাবে সংরক্ষণ করা।

## 21. Software Maintenance
**English:** Software maintenance modifies software after delivery to fix defects, adapt to changes, improve performance, or add functionality.  
**বাংলা:** Delivery-এর পরে bug fix, environment change, improvement বা নতুন feature-এর জন্য software modify করা।

## 22. Corrective Maintenance
**English:** Corrective maintenance fixes discovered faults or defects.  
**বাংলা:** Existing bug/error fix করা।

## 23. Adaptive Maintenance
**English:** Adaptive maintenance changes software so it continues to work in a changed environment.  
**বাংলা:** OS, hardware, business rule বা environment change হলে software adapt করা।

## 24. Perfective Maintenance
**English:** Perfective maintenance improves performance, usability, or functionality without necessarily fixing a fault.  
**বাংলা:** Performance, usability বা feature improve করা।

## 25. Preventive Maintenance
**English:** Preventive maintenance improves software maintainability or structure to reduce the likelihood of future problems.  
**বাংলা:** Future problem কমানোর জন্য code/design improve করা।

## 26. Software Support Tools
**English:** Software support tools assist activities such as requirements management, design, coding, testing, configuration management, and project tracking.  
**বাংলা:** Development process-এর বিভিন্ন কাজ automate/support করার tools।

## 27. CASE Tools
**English:** Computer-Aided Software Engineering (CASE) tools support software engineering activities such as modeling, documentation, testing, or project management.  
**বাংলা:** Software engineering-এর বিভিন্ন activity computer-based tool দিয়ে support/automate করা।

## 28. Software Project
**English:** A software project is a planned effort to develop, deliver, modify, or maintain a software product within defined constraints.  
**বাংলা:** নির্দিষ্ট time, cost, scope-এর মধ্যে software তৈরি/maintain করার planned কাজ।

## 29. Software Project Organization
**English:** Project organization defines roles, responsibilities, authority, communication paths, and team structure for software development.  
**বাংলা:** কে কী কাজ করবে, কার responsibility কী, communication কীভাবে হবে—এসব define করে।

## 30. Project Management
**English:** Software project management plans, organizes, monitors, and controls resources, schedule, cost, scope, risks, and quality.  
**বাংলা:** Time, cost, people, scope, risk ও quality manage করে project সফলভাবে complete করা।

## 31. Risk Management
**English:** Risk management identifies, analyzes, prioritizes, and controls uncertainties that may affect a software project.  
**বাংলা:** Project-এর সম্ভাব্য সমস্যা আগে identify করে impact কমানোর plan করা।

## 32. Quality Assurance (SQA)
**English:** Software Quality Assurance is a planned set of activities that helps ensure software processes and products meet defined quality standards.  
**বাংলা:** Software process ও product-এর quality maintain করার systematic activities।

## 33. Quality
**English:** Software quality is the degree to which software satisfies stated requirements, user needs, and relevant quality attributes.  
**বাংলা:** Software requirement ও user expectation কত ভালোভাবে satisfy করে সেটাই quality।

## 34. Communication Skills
**English:** Effective communication ensures that developers, managers, customers, and stakeholders understand requirements, decisions, progress, and issues.  
**বাংলা:** Team ও stakeholder-এর মধ্যে clear communication ভুল ও misunderstanding কমায়।

## 35. Software Development Life Cycle (SDLC)
**English:** SDLC is a framework covering major software activities such as requirements, design, implementation, testing, deployment, and maintenance.  
**বাংলা:** Software-এর পুরো lifecycle-এর structured stages হলো SDLC।

## 36. Waterfall Model
**English:** Waterfall is a sequential development model where major phases are performed in a largely ordered progression.  
**বাংলা:** Requirement → Design → Implementation → Testing → Deployment-এর মতো sequential approach।

## 37. Agile
**English:** Agile is an iterative and incremental approach emphasizing frequent delivery, customer feedback, adaptation, and collaboration.  
**বাংলা:** ছোট ছোট iteration-এ software develop করে frequent feedback অনুযায়ী change করা হয়।

## 38. Prototype
**English:** A prototype is an early version of a system used to explore requirements, design ideas, or user feedback.  
**বাংলা:** Final product-এর আগে early model বানিয়ে requirement/design validate করা।

## 39. Design
**English:** Software design transforms requirements into an architecture, components, interfaces, data structures, and detailed solution structure.  
**বাংলা:** Requirement থেকে system কীভাবে implement হবে তার blueprint তৈরি করা।

## 40. Architecture
**English:** Software architecture describes the major components of a system and their relationships and interactions.  
**বাংলা:** System-এর high-level structure—major component ও তাদের interaction।

## 41. Interface
**English:** An interface defines how a software component communicates with other components or external systems.  
**বাংলা:** দুই component কীভাবে একে অপরের সাথে communicate করবে তার contract।

# CSE 321 — OPERATING SYSTEMS

## 42. Operating System
**English:** An operating system is system software that manages computer hardware/resources and provides services and abstractions for applications.  
**বাংলা:** Hardware/resource manage করে application-কে service দেওয়ার system software হলো OS।

## 43. OS Design Objectives
**English:** Common OS objectives include convenience, efficient resource utilization, reliability, security, scalability, and good performance.  
**বাংলা:** User convenience, resource efficiency, security, reliability ও performance নিশ্চিত করা OS-এর প্রধান objective।

## 44. Process
**English:** A process is a program in execution together with its current state and associated resources.  
**বাংলা:** চলমান program-এর execution instance হলো process।

## 45. Program vs Process
**English:** A program is a passive set of instructions; a process is an active executing instance of a program.  
**বাংলা:** Program static code; process হলো সেই code-এর running instance।

## 46. Sequential Process
**English:** A sequential process executes instructions in a defined order, with one instruction flow progressing at a time.  
**বাংলা:** Instruction ধারাবাহিকভাবে একটার পর একটা execute করে।

## 47. Concurrent Process
**English:** Concurrent processes make progress during overlapping periods and may execute independently or interact with shared resources.  
**বাংলা:** একাধিক process একই সময়ে/overlapping সময়ে progress করে।

## 48. Process Cooperation
**English:** Cooperating processes interact or share information to achieve a common task, often using inter-process communication or shared resources.  
**বাংলা:** একাধিক process data/resource share করে একসাথে কাজ করে।

## 49. Inter-Process Communication (IPC)
**English:** IPC provides mechanisms for processes to exchange data and coordinate execution, such as shared memory and message passing.  
**বাংলা:** Process-এর মধ্যে data exchange ও coordination-এর mechanism।

## 50. Mutual Exclusion
**English:** Mutual exclusion ensures that at most one process/thread at a time executes a critical section for a shared resource.  
**বাংলা:** Shared resource-এর critical section-এ একই সময়ে সর্বোচ্চ একটি process ঢুকতে পারে।

## 51. Critical Section
**English:** A critical section is a portion of code that accesses shared data/resources and must be protected from unsafe concurrent execution.  
**বাংলা:** Shared data/resource access করা sensitive code অংশ।

## 52. Race Condition
**English:** A race condition occurs when the result depends on the timing or order of concurrent operations on shared data.  
**বাংলা:** Multiple process-এর execution order-এর ওপর result depend করলে race condition হয়।

## 53. Semaphore
**English:** A semaphore is a synchronization primitive represented by an integer-like value and accessed through atomic operations such as wait and signal.  
**বাংলা:** Process synchronization ও resource control-এর জন্য semaphore ব্যবহার করা হয়।

## 54. Binary Semaphore
**English:** A binary semaphore has two logical states and is commonly used for mutual exclusion or simple signaling.  
**বাংলা:** দুই state-এর semaphore, সাধারণত lock/synchronization-এর জন্য ব্যবহৃত হয়।

## 55. Counting Semaphore
**English:** A counting semaphore can represent multiple available instances of a resource.  
**বাংলা:** একাধিক identical resource available আছে কিনা count করে।

## 56. Deadlock
**English:** Deadlock is a state where a set of processes are permanently blocked because each is waiting for a resource/event that cannot become available.  
**বাংলা:** Process-গুলো এমনভাবে একে অপরের resource-এর জন্য wait করে যে কেউই এগোতে পারে না।

## 57. Four Necessary Conditions of Deadlock
**English:** Mutual exclusion, hold and wait, no preemption, and circular wait are the four necessary conditions.  
**বাংলা:** এই চারটি condition একসাথে থাকলে deadlock সম্ভব: mutual exclusion, hold & wait, no preemption, circular wait।

## 58. Deadlock Prevention
**English:** Deadlock prevention designs the system so at least one necessary deadlock condition can never hold.  
**বাংলা:** Deadlock-এর necessary condition ভেঙে দিয়ে deadlock prevent করা।

## 59. Deadlock Avoidance
**English:** Deadlock avoidance dynamically allocates resources only when the resulting state remains safe; Banker’s algorithm is a classic example.  
**বাংলা:** Resource দেওয়ার আগে system safe state-এ থাকবে কিনা check করা হয়।

## 60. Deadlock Detection
**English:** Deadlock detection allows deadlocks to occur and then identifies them so recovery can be performed.  
**বাংলা:** Deadlock হতে দেয়, পরে detect করে recovery করে।

## 61. Deadlock Recovery
**English:** Recovery resolves a detected deadlock by actions such as terminating processes or preempting/reallocating resources where possible.  
**বাংলা:** Deadlock detect হওয়ার পরে process terminate বা resource পুনর্বণ্টন করে system recover করা।

## 62. CPU Scheduling
**English:** CPU scheduling selects which ready process should receive the CPU next.  
**বাংলা:** Ready queue থেকে কোন process CPU পাবে তা determine করে।

## 63. Scheduler
**English:** A scheduler is the OS component/algorithm that selects processes for execution according to scheduling policies.  
**বাংলা:** CPU-এর জন্য next process select করে।

## 64. Dispatcher
**English:** The dispatcher gives control of the CPU to the process selected by the scheduler, including context-switch and related actions.  
**বাংলা:** Scheduler process select করার পরে actual CPU control সেই process-কে দেয়।

## 65. Scheduling Criteria
**English:** Common criteria include CPU utilization, throughput, turnaround time, waiting time, response time, and fairness.  
**বাংলা:** CPU কতটা busy, কত process complete, কত সময় লাগে, response কেমন—এসব দিয়ে scheduling evaluate করা হয়।

## 66. FCFS
**English:** First-Come, First-Served schedules processes in order of arrival and is normally non-preemptive.  
**বাংলা:** যে process আগে আসে সে আগে CPU পায়।

## 67. SJF
**English:** Shortest Job First selects the ready process with the smallest expected CPU burst; it minimizes average waiting time under ideal assumptions.  
**বাংলা:** সবচেয়ে ছোট CPU burst-এর process আগে চলে।

## 68. SRTF
**English:** Shortest Remaining Time First is the preemptive version of SJF, selecting the process with the shortest remaining CPU time.  
**বাংলা:** SJF-এর preemptive version; remaining time সবচেয়ে কম process আগে।

## 69. Round Robin
**English:** Round Robin gives each ready process a fixed time quantum in cyclic order and is designed for time-sharing systems.  
**বাংলা:** প্রত্যেক process-কে fixed time quantum দিয়ে turn-by-turn CPU দেওয়া হয়।

## 70. Priority Scheduling
**English:** Priority scheduling selects the highest-priority ready process according to the chosen priority rule.  
**বাংলা:** Highest priority process আগে CPU পায়।

## 71. Preemptive Scheduling
**English:** In preemptive scheduling, the OS can interrupt a running process and allocate the CPU to another process.  
**বাংলা:** Running process-কে interrupt করে CPU অন্য process-কে দেওয়া যায়।

## 72. Non-Preemptive Scheduling
**English:** In non-preemptive scheduling, a running process generally keeps the CPU until it terminates, blocks, or voluntarily yields.  
**বাংলা:** Running process নিজে CPU ছাড়ার আগে সাধারণত CPU কেড়ে নেওয়া হয় না।

## 73. Context Switch
**English:** A context switch saves the state of one process/thread and restores the state of another so execution can switch.  
**বাংলা:** এক process-এর state save করে অন্য process-এর state load করা।

## 74. Job Control Language
**English:** Job Control Language (JCL) is used in systems such as IBM mainframes to describe jobs and specify resources, programs, and processing steps.  
**বাংলা:** Mainframe environment-এ job কীভাবে execute হবে ও কোন resource লাগবে তা specify করার language।

## 75. Memory Management
**English:** Memory management tracks, allocates, protects, and reclaims main memory for processes.  
**বাংলা:** RAM-এর space process-দের allocate/protect/manage করা।

## 76. Address Binding
**English:** Address binding maps program instructions/data references to actual memory addresses; it can occur at compile, load, or execution time depending on the system.  
**বাংলা:** Program-এর address/reference কীভাবে actual memory address-এ map হবে তা address binding।

## 77. Logical Address
**English:** A logical (virtual) address is an address generated by the CPU/program before translation to a physical memory address.  
**বাংলা:** CPU/program থেকে generate হওয়া address, physical RAM address নয়।

## 78. Physical Address
**English:** A physical address identifies an actual location in main memory.  
**বাংলা:** RAM-এর actual memory location-এর address।

## 79. Paging
**English:** Paging divides logical memory into fixed-size pages and physical memory into frames, allowing non-contiguous allocation.  
**বাংলা:** Logical memory page এবং physical memory frame-এ ভাগ করে memory efficiently manage করা হয়।

## 80. Page
**English:** A page is a fixed-size block of a process's virtual/logical address space.  
**বাংলা:** Virtual memory-এর fixed-size block হলো page।

## 81. Frame
**English:** A frame is a fixed-size block of physical memory into which a page can be loaded.  
**বাংলা:** Physical RAM-এর fixed-size block হলো frame।

## 82. Page Table
**English:** A page table maps virtual page numbers to physical frame numbers.  
**বাংলা:** কোন page কোন physical frame-এ আছে তা map করে।

## 83. Virtual Memory
**English:** Virtual memory gives processes an address space larger than available physical memory by using secondary storage and memory-management techniques.  
**বাংলা:** RAM-এর চেয়ে বড় logical memory space ব্যবহার করার technique।

## 84. Swapping
**English:** Swapping moves processes or portions of their memory between main memory and secondary storage to manage limited RAM.  
**বাংলা:** RAM ও secondary storage-এর মধ্যে process/memory data move করা।

## 85. Store Multiplexing
**English:** Store multiplexing refers to techniques that allow limited main storage to support multiple processes through memory sharing, allocation, or virtual-memory mechanisms.  
**বাংলা:** Limited memory-কে multiple process-এর মধ্যে efficiently ব্যবহার করার ধারণা।

## 86. Time Sharing
**English:** Time sharing gives multiple users/processes short CPU time slices so the system appears to run them interactively at the same time.  
**বাংলা:** ছোট ছোট time slice দিয়ে multiple user/process-কে CPU share করানো।

## 87. Batch Processing
**English:** Batch processing executes collected jobs with little or no interactive user involvement during execution.  
**বাংলা:** User interaction ছাড়াই job group করে execute করা।

## 88. File System
**English:** A file system organizes, stores, names, protects, and retrieves files and directories on storage devices.  
**বাংলা:** File/directory organize, store, access ও protect করার OS mechanism।

## 89. File
**English:** A file is a named collection of related data stored and managed by the operating system.  
**বাংলা:** OS-managed named data collection হলো file।

## 90. Directory
**English:** A directory is a structure used to organize and reference files and possibly other directories.  
**বাংলা:** File ও subdirectory organize করার structure।

## 91. File Security
**English:** File security controls who can access, modify, execute, or otherwise use stored files.  
**বাংলা:** File কে read/write/execute করতে পারবে তা permissions/security দিয়ে control করা হয়।

## 92. Device Driver
**English:** A device driver is software that provides an interface between the OS and a specific hardware device.  
**বাংলা:** OS ও hardware device-এর মধ্যে communication করানোর software।

## 93. Multiprocessing
**English:** Multiprocessing uses two or more processing units/cores to execute processes or threads concurrently.  
**বাংলা:** Multiple CPU/core ব্যবহার করে parallel বা concurrent processing করা।

## 94. Resource Sharing
**English:** Resource sharing allows multiple processes/users to use system resources such as CPU, memory, storage, and devices under OS control.  
**বাংলা:** OS controlledভাবে multiple process/user-কে resource use করতে দেয়।

## 95. Protection
**English:** Protection controls access to system resources so processes operate within authorized boundaries.  
**বাংলা:** Process যেন unauthorized resource access করতে না পারে তা control করা।

## 96. Security
**English:** OS security protects the system and data from unauthorized access, misuse, attacks, and other threats.  
**বাংলা:** System ও data-কে unauthorized access/attack থেকে protect করা।

## 97. OS Design and Implementation
**English:** OS design defines system structure and policies; implementation translates those designs into working mechanisms, often with low-level programming and hardware interfaces.  
**বাংলা:** OS কীভাবে structured হবে তা design, আর সেটাকে actual working system-এ convert করা implementation।

## 98. Performance Evaluation
**English:** OS performance evaluation measures metrics such as throughput, response time, CPU utilization, latency, and resource efficiency.  
**বাংলা:** OS কত efficiently কাজ করছে তা বিভিন্ন performance metric দিয়ে measure করা।

## 99. Case Study
**English:** An OS case study examines the design, mechanisms, and behavior of a real operating system to understand practical implementation.  
**বাংলা:** Real OS-এর design ও implementation study করে practical concept বোঝা।

# IMPORTANT DIFFERENCES

## Functional vs Non-Functional Requirement
**Functional:** What the system does.  
**Non-functional:** How well/under what constraints it operates.  
**বাংলা:** Functional = কাজ কী; Non-functional = কাজের quality/constraint কী।

## Verification vs Validation
**Verification:** Building the product right.  
**Validation:** Building the right product.  
**বাংলা:** Specification বনাম user need।

## Cohesion vs Coupling
**Cohesion:** Relatedness inside a module → high is good.  
**Coupling:** Dependency between modules → low is good.  
**বাংলা:** Module-এর ভিতরের সম্পর্ক বনাম module-এর মধ্যকার dependency।

## Corrective vs Adaptive vs Perfective vs Preventive
**Corrective:** Fix bugs.  
**Adaptive:** Adapt to environment changes.  
**Perfective:** Improve performance/features/usability.  
**Preventive:** Reduce future maintenance problems.  
**বাংলা:** Bug fix → environment change → improvement → future problem prevention।

## Process vs Program
**Program:** Passive code/instructions.  
**Process:** Program in execution.  
**বাংলা:** Program static; process running।

## Sequential vs Concurrent Process
**Sequential:** One defined execution flow.  
**Concurrent:** Multiple processes make overlapping progress.  
**বাংলা:** একটার পর একটা বনাম overlapping execution।

## Mutual Exclusion vs Synchronization
**Mutual Exclusion:** Ensures one process at a time enters a critical section.  
**Synchronization:** Coordinates multiple processes' execution/order.  
**বাংলা:** একসাথে ঢোকা বন্ধ করা বনাম overall coordination।

## Deadlock Prevention vs Avoidance vs Detection
**Prevention:** Break a necessary condition.  
**Avoidance:** Allocate only if state remains safe.  
**Detection:** Detect deadlock after it may occur.  
**বাংলা:** আগে condition ভাঙা → safe state check → পরে detect করা।

## FCFS vs SJF vs Round Robin
**FCFS:** Arrival order.  
**SJF:** Shortest burst first.  
**RR:** Fixed time quantum in rotation.  
**বাংলা:** Arrival → shortest job → time-slice based।

## Preemptive vs Non-Preemptive
**Preemptive:** OS can interrupt running process.  
**Non-preemptive:** Process generally keeps CPU until it blocks/finishes/yields.  
**বাংলা:** CPU কেড়ে নেওয়া যায় বনাম যায় না।

## Paging: Page vs Frame
**Page:** Fixed-size block of virtual/logical memory.  
**Frame:** Fixed-size block of physical memory.  
**বাংলা:** Page = virtual; Frame = physical।

## Logical vs Physical Address
**Logical:** Generated by CPU/program.  
**Physical:** Actual RAM address after translation.  
**বাংলা:** CPU-generated বনাম actual memory location।

## Time Sharing vs Batch Processing
**Time Sharing:** Interactive, CPU shared among users/processes using time slices.  
**Batch:** Jobs processed with little/no interaction.  
**বাংলা:** Interactive sharing বনাম non-interactive job execution।

## Multiprocessing vs Multitasking
**Multiprocessing:** Uses multiple processors/cores.  
**Multitasking:** Multiple tasks/processes share CPU time; may occur on one or multiple cores.  
**বাংলা:** Multiple processing units বনাম multiple tasks-এর execution।

## Protection vs Security
**Protection:** Controls authorized access among system entities.  
**Security:** Broader defense against unauthorized access and threats.  
**বাংলা:** Internal access control বনাম broader system defense।

# LAST-MINUTE VIVA — 30 MUST KNOW

1. **What is software engineering?** A systematic and disciplined approach to software development, operation, and maintenance.
2. **What is a requirement?** A required service, behavior, or constraint of a system.
3. **Functional vs non-functional?** What the system does vs quality/constraints.
4. **What is modularity?** Dividing a system into smaller manageable modules.
5. **What is cohesion?** Degree of relatedness within a module.
6. **What is coupling?** Degree of dependency between modules.
7. **What is verification?** Checking conformance to specifications.
8. **What is validation?** Checking whether the product satisfies user needs.
9. **What is software maintenance?** Post-delivery modification to fix, adapt, improve, or prevent problems.
10. **What is SQA?** Planned activities to ensure software process/product quality.
11. **What is an OS?** System software that manages hardware/resources and provides services to applications.
12. **Program vs process?** Program is passive code; process is a running instance.
13. **What is a concurrent process?** A process that makes progress overlapping in time with other processes.
14. **What is a critical section?** Code that accesses shared resources and needs synchronization.
15. **What is mutual exclusion?** At most one process executes a protected critical section at a time.
16. **What is a semaphore?** A synchronization primitive for controlling access/signaling.
17. **What is deadlock?** Permanent waiting caused by circular resource dependencies.
18. **Four deadlock conditions?** Mutual exclusion, hold and wait, no preemption, circular wait.
19. **Prevention vs avoidance?** Prevention breaks a necessary condition; avoidance keeps the system safe.
20. **What is CPU scheduling?** Selecting the next ready process for CPU execution.
21. **What is FCFS?** Scheduling in arrival order.
22. **What is SJF?** Scheduling the shortest expected CPU burst first.
23. **What is Round Robin?** Time-quantum-based cyclic scheduling.
24. **What is context switch?** Saving one execution context and restoring another.
25. **What is paging?** Dividing virtual memory into pages and physical memory into frames.
26. **Page vs frame?** Page is virtual; frame is physical.
27. **Logical vs physical address?** CPU-generated address vs actual RAM address.
28. **What is virtual memory?** Technique providing a larger logical address space than available physical memory.
29. **What is a file system?** OS mechanism for organizing and managing files/directories on storage.
30. **What is a device driver?** Software interface between the OS and a hardware device.
